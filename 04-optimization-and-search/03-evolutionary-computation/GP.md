# Final Summary — Genetic Programming (GP)

## 1. Overview

Genetic Programming (GP) is an evolutionary computation method that evolves computer programs or mathematical expressions instead of fixed-length vectors.

Unlike Genetic Algorithm (GA), where individuals are represented as chromosomes, GP represents solutions as tree structures.

The main idea is to automatically discover a mathematical expression or program that minimizes the difference between predicted and target outputs.

---

# 2. Representation: Expression Tree

In GP, each individual is represented as a tree.

Example:

$(x+2)\times x$


Tree representation:

      *
    /   \
   +     x
  / \
 x   2



Each node can represent:

- Function:
    - +
    - -
    - *
    - /
    - sin
    - cos

- Terminal:
    - input variables (x)
    - constants


The representation is the most important component in GP because it determines the search space and possible solutions.

---

# 3. Population Initialization

The initial population is generated by creating random expression trees.

Example:
Tree 1:

(x+3)*x

Tree 2:

sin(x)+2

Tree 3:

(x*x)-1



The population provides multiple candidate programs that evolve over generations.

---

# 4. Fitness Evaluation

For symbolic regression problems, the fitness function measures the difference between the generated expression and the target function.

The Mean Squared Error (MSE) was used:

$MSE=
\frac{1}{N}
\sum_{i=1}^{N}
(y_i-\hat{y_i})^2$


Lower fitness values indicate better solutions.

In the Advanced GP version, a complexity penalty was added:

$Fitness =
MSE+\lambda Size(Tree)$


This encourages simpler expressions and reduces the Bloat problem.

---

# 5. Selection

Tournament Selection was used.

The process:

1. Randomly select several individuals.
2. Compare their fitness values.
3. Select the best individual as parent.


Tournament selection provides a balance between:

- Exploitation (selecting good solutions)
- Exploration (maintaining diversity)

---

# 6. Crossover in GP

Unlike GA, crossover in GP operates on subtrees.

Two parent trees exchange randomly selected subtrees.

Example:

Parent 1:

  *
 / \
x   2


Parent 2:

  +
 / \
x   5


After subtree crossover:

  *
 / \
x   5


Crossover allows GP to combine useful parts of existing programs.

---

# 7. Mutation in GP

Mutation changes part of a tree by replacing a subtree with a newly generated random subtree.

Example:

Before:

$(x+2)$


After:

$sin(x)$


Mutation introduces diversity and prevents premature convergence.

---

# 8. Basic GP vs Advanced GP

Two implementations were evaluated.

## Basic GP

Characteristics:

- Binary tree representation
- Operators:
    - +
    - -
    - *
    - /
- Fixed terminals


Advantages:

- Smaller search space
- Faster convergence for simple mathematical functions


Limitations:

- Limited expression flexibility
- Cannot naturally represent complex nonlinear functions


---

## Advanced GP

Improvements:

- Flexible tree representation using children lists
- Unary functions:
    - sin
    - cos
    - exp
    - log
- Random constant generation
- Protected mathematical operations
- Complexity control


Advantages:

- Larger expression space
- More suitable for nonlinear symbolic regression


Limitations:

- Larger search space
- Higher risk of expression bloat
- Requires careful parameter tuning

---

# 9. Experimental Results

Three symbolic regression problems were evaluated.

---

## Experiment 1

Target:

$y=x^2+2x+1$


Basic GP:

$Fitness \approx 0$


Advanced GP:

$Fitness \approx 0.073$


Basic GP performed better because the target function was a simple polynomial.

---

## Experiment 2

Target:

$y=x^3+2x^2-3x+5$


Basic GP:

$Fitness \approx 0$


Advanced GP:

$Fitness \approx 0.325$


The result showed that a simpler representation can outperform a more flexible one when the problem structure matches the search space.

---

## Experiment 3

Target:

$y=sin(x)+0.5cos(2x)$


Basic GP:

$Fitness \approx 0.418$


Advanced GP:

Performance was degraded because the large function set created a very large search space and caused expression complexity growth.

---

# 10. Main Observations

The experiments demonstrated:

1. A larger representation does not always guarantee better performance.

2. The choice of function set should match the problem characteristics.

3. GP performance strongly depends on:
    - Representation
    - Function set
    - Mutation and crossover operators
    - Complexity control


For polynomial problems, simple GP representations can be highly effective.

For nonlinear problems, advanced representations provide more modeling capability but require stronger control mechanisms.

---

|Algorithm|Representation|Main Operation|Typical Problems|
|-|-|-|-|
|GA|Chromosome / Vector|Crossover + Mutation|Optimization problems|
|DE|Real-valued Vector|Differential Mutation|Continuous optimization|
|GP|Expression Tree|Subtree Crossover|Symbolic Regression|

---

# Final Conclusion

Genetic Programming extends evolutionary computation from optimizing numerical parameters to discovering complete mathematical expressions.

The experiments showed that successful GP optimization depends not only on evolutionary operators but also on designing an appropriate representation and search space.

A well-designed representation can significantly improve the ability of GP to discover meaningful solutions.
